# 📦 FilamentStorageBot

**FilamentStorageBot** — це спеціалізована інформаційна система у форматі Telegram-бота, розроблена для автоматизації обліку та моніторингу витратних матеріалів (філаменту та фотополімерної смоли) у сфері 3D-друку. Система дозволяє підтримувати актуальний стан складу, відстежувати історію використання та вчасно отримувати сповіщення про необхідність закупівлі нових матеріалів.

---

## 🚀 Процес запуску локально (How to run locally)

Для успішного розгортання проєкту на локальній машині (використовуючи стек **MAMP/XAMPP**):

1.  **Клонування репозиторію:**
    ```bash
    git clone [https://github.com/A1kanar0/FilamentStorageBot.git](https://github.com/A1kanar0/FilamentStorageBot.git)
    cd FilamentStorageBot
    ```

2.  **Налаштування бази даних:**
    * Створіть нову БД з назвою `filament_db` у **phpMyAdmin**.
    * Встановіть зіставлення (Collation): `utf8mb4_0900_ai_ci`.
    * Імпортуйте файл `database.sql` для створення структури таблиць (`users`, `consumables`, `usage_logs`, `user_states`).

3.  **Конфігурація:**
    * У файлі `config.php` вкажіть ваш унікальний `BOT_TOKEN` від @BotFather.
    * Налаштуйте параметри підключення до БД (сервер, порт, логін та пароль) у файлі `src/Database/DatabaseConnection.php`.

4.  **Встановлення Webhook:**
    * Запустіть локальний сервер (за замовчуванням порт 8888).
    * Прокиньте порт через **ngrok** для отримання HTTPS: `ngrok http 8888`.
    * Зареєструйте Webhook в Telegram:
      `https://api.telegram.org/bot<TOKEN>/setWebhook?url=<NGROK_HTTPS_URL>/index.php`

## 🛠 Опис функціональності (Functionality)

Система реалізує повний спектр можливостей для управління матеріалами:

* **Автоматична ідентифікація:** При першому зверненні бот автоматично реєструє користувача в системі, створюючи персоналізований запис у базі даних.
* **Інтелектуальне управління складом:**
    * **Додавання матеріалів:** Користувач може вносити дані про бренд, тип пластику (PLA, ABS, PETG, TPU), колір та початкову вагу котушки.
    * **Функція "Відродження":** При спробі додати вже існуючий, але вичерпаний матеріал (вага 0), система пропонує оновити дані старої котушки, що запобігає дублюванню записів.
* **Оперативне списання (Usage Tracking):**
    * **Машина станів (FSM):** Реалізовано покроковий процес вибору матеріалу та введення ваги витраченого пластику через інтерактивне меню.
    * **Журналювання:** Кожна транзакція автоматично записується в історію (`usage_logs`) із зазначенням ID користувача, дати та об'єму списання.
* **Моніторинг та аналітика:**
    * **Актуальні залишки:** Перегляд списку всіх матеріалів на складі з виводом їх поточної ваги в грамах.
    * **Smart-сповіщення:** Автоматичне підсвічування позицій, залишок яких становить менше 100 грамів (критичний поріг).
    * **Історія дій:** Можливість переглянути 10 останніх операцій по складу для аудиту витрат.

## 🏗 Programming Principles (Принципи програмування)

Проєкт розроблено з дотриманням принципів чистого коду та SOLID:

1.  **Single Responsibility Principle (SRP):** Кожен клас відповідає за одну задачу. Наприклад, `UsageLogRepository` займається лише логуванням операцій, не втручаючись у логіку користувачів.
2.  **Dependency Inversion Principle (DIP):** Високорівневі компоненти (сервіси) залежать від інтерфейсів, а не від конкретних реалізацій, що дозволяє легко замінити, наприклад, MySQL на іншу БД.
3.  **Interface Segregation Principle (ISP):** Інтерфейси розділені за функціональним призначенням, що запобігає нагромадженню зайвих методів у класах.
4.  **DRY (Don't Repeat Yourself):** Логіка формування повторюваних елементів (інлайн-кнопок, головного меню) винесена в окремі утиліти в класі `TelegramBot`.
5.  **KISS (Keep It Simple, Stupid):** Архітектура побудована на прямих взаємодіях команд без зайвих рівнів абстракції там, де це не потрібно.

## 🎨 Design Patterns (Патерни проєктування)

Для забезпечення гнучкості системи використано наступні патерни:

* **Singleton:** Гарантує створення лише одного підключення до бази даних у класі `DatabaseConnection`.
* **Repository:** Ізолює логіку доступу до даних від бізнес-логіки додатка, забезпечуючи чистоту SQL-запитів.
* **Command:** Кожна функція бота (Start, Add, Status) виділена в окремий клас-команду з єдиним методом виконання.
* **Factory:** Клас `CommandFactory` динамічно створює об'єкти необхідних команд, що полегшує масштабування функціоналу бота.

## 🔧 Refactoring Techniques (Техніки рефакторингу)

Проєкт пройшов стадію глибокого рефакторингу:

1. **Replace Conditional with Polymorphism (Заміна умовних операторів поліморфізмом):** Замість громіздких конструкцій `switch-case` або `if-else` для обробки кожної команди у контролері, було впроваджено паттерн **Command**. Кожна дія бота тепер є окремим класом, що дозволяє системі бути «відкритою для розширення, але закритою для модифікації» (принцип OCP).
2. **Introduce Dependency Injection (Впровадження ін’єкції залежностей):** Було відмовлено від ручного створення об’єктів усередині класів (наприклад, `new Repository()`). Тепер усі залежності передаються через конструктор за допомогою інтерфейсів. Це дозволило реалізувати принцип інверсії залежностей (DIP) та значно полегшило тестування окремих модулів.
3. **Extract Interface (Виділення інтерфейсу):** Для всіх ключових сервісів та репозиторіїв (напр. `StateServiceInterface`) було створено інтерфейси. Це забезпечує «слабку пов’язаність» (Low Coupling) між компонентами системи та дозволяє легко змінювати реалізацію сховища чи логіки станів без переписування всього проєкту.
4. **Replace Magic Literal with Constant (Заміна магічних рядків константами):** Всі текстові елементи інтерфейсу (назви кнопок) та назви станів (FSM) винесені в окремі класи констант. Це забезпечує принцип «Single Source of Truth» — будь-яка зміна в UI бота тепер робиться в одному конфігураційному файлі.
5. **Extract Class (Виділення класу):** Складна логіка управління станами (Finite State Machine) та робота з даними були винесені з контролера у спеціалізовані класи `StateService` та відповідні репозиторії. Це розвантажило контролер, залишивши йому лише роль координатора потоків повідомлень.
